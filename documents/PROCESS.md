# PROCESS.md — 我的練習心得

> 一個原則：**寫「具體發生的事」，不寫感想文。**
> 貼上當時真實的 prompt、真實的數字、真實的錯誤訊息——三個月後的你（和你的同事）才用得上。

#### 使用的 agent 與模型：GPT 5.6 - Terra

## 通用四問

### 1. 我的任務拆解

（開工前你把任務拆成哪幾步？實際做的時候順序有變嗎？為什麼變？）

- 分為以下幾步
1. 理解問題與需求
2. 分析困難度 & 可拆分成幾個步驟（先寫詳細文檔，編寫，用另一個subagent去對比文檔與git diff是否一致）
3. 根據困難度分析使用哪個模組與effort
4. 分析是否有重複性可循，如何拆分成可自動化

有變，因為有提供範例，且讀了之後發現可用，且改動較小，為了節省token就用了最簡單的方式不殺雞用牛刀

### 2. AI 幫上大忙的地方

（哪件事 agent 做得又快又好？**貼上當時的提問原文**，說明為什麼這樣問有效。）

- 原文隨著session消失了，但有時候在表達某些問題或情況時，用了大概的描述，讓AI自動去分辨並優化後，能明顯感覺得到描述得更詳細，更適合AI自己去讀並操作，減少產出錯誤的風險

### 3. AI 誤導我的地方，與我如何發現

（agent 說錯／改錯／過度自信的時刻。你靠什麼抓到——對照程式碼？頁面實測？跑測試？）

- 頁面報錯但仍表示測試OK，並未實際操作一整個流程，實際有錯誤但很有自信的說全部測試OK，需要再反復確認甚至貼上錯誤訊息才會繼續過度自信的修復

### 4. 我會帶回日常工作的一招

（一個具體、可複製的做法，不要寫「要多驗證」這種口號——寫出**操作步驟**。）

- 針對自己的項目創建適合的skill 與 workflow，先寫出一個你想要的格式作為參考讓AI去判斷應該怎麼寫出改步驟、skill，再自己審核是否與你想象中的流程一致，再用另一個agent幫你找看看有沒有死角或盲區

## 自我驗證（做到哪個階段答哪題）

### 第一階段 — Agentic Coding

練習 1

1. 我能不看筆記說出三個專案（Web/Core/Infrastructure）各自的職責 Y
2. 我核對過 agent 描述的建單流程，且**至少找出一處不精確或過度簡化的說法** Y
3. 我知道商業邏輯應該放在哪一層、新增頁面要動哪些地方 Y

練習 2

1. 三個 bug 我都先在頁面上重現過，才開始找程式 Y
2. 我給 agent 的資訊包含具體觀察（頁碼／金額數字／庫存數字），而不是只貼客訴原文 Y
3. 每個修復都回到頁面驗證過症狀消失 Y
4. 每個 bug 都補了一個回歸測試，`dotnet test` 全綠 Y
5. 三個獨立 commit，message 說明症狀與根因 Y N
6. （思考題）為什麼原本的測試沒抓到這三個 bug？界面UI需要另外設置，且單元測試沒問題需要後續加上Integration Test更完整

練習 3

1. `/Products/LowStock` 不帶參數 → 門檻 10 的結果；帶 `?threshold=3` → 結果隨之改變 Y
2. `?threshold=0`、`?threshold=-1` → 頁面顯示驗證錯誤，不是 500 Y
3. 售出數量欄位排除了 Cancelled 訂單（可用一筆已取消的訂單驗證） Y
4. 停售（已停售 badge）商品不出現在列表 Y
5. 程式分層與命名跟既有的 Products 功能一致（請 agent 自我 review 一次，並自己確認） Y
6. 至少 3 個新測試，`dotnet test` 全綠 Y

練習 4

1. 重構後 `dotnet test` 全綠 Y
2. 我能說出這次重構「改善了什麼、沒有改變什麼」 Y
3. 我有在 code review 的角度看過 diff（不是 agent 說好就好） Y
